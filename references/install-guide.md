# 经方问询助手（TCM Inquiry Agent）
## 安装与使用手册

**版本**：2.0  
**适用**：中医小诊所医师、助手、管理员  
**仓库**：[sandy01384007/tcm-inquiry-agent](https://github.com/sandy01384007/tcm-inquiry-agent)

本产品分两层，不要混用边界：

| 层 | 是什么 | 能做什么 |
|---|---|---|
| 经方诊室 App | 诊所日常页面 | 看诊采集、方证草稿、煎煮说明、舌象与检验辅助解读、收费、AI 医生 |
| 本仓库 Skill | 理论与安全规则 | 给助手加载规则、词表、测试用例；可选接到 Dify / 本机模型 |

**不是自动医生。** 方证、煎煮、西药对症、舌象、检验、收费和对话，都只给执业中医师作草稿，必须面诊复核。附子、承气等高风险方不给出可照做的家庭克数。急症只提醒急救。

## 一、安装前准备

| 项目 | 最低 | 说明 |
|---|---|---|
| 电脑 | 4 核 / 8 GB | 只开网页即可；本机大模型建议 16 GB 以上 |
| 系统 | Windows 10、macOS、Ubuntu 22.04 | 诊所前台电脑即可 |
| 浏览器 | Chrome 或 Edge | 语音输入依赖这两款 |
| 网络 | 可上网 | 不用云端模型时可只走本机 Ollama |
| 人员 | 至少一名执业中医师 | 助手只能采集，不能核定处方 |

可选：

- 云端视觉与对话：服务器环境变量 `XAI_API_KEY`
- 完全本地： [Ollama](https://ollama.com)

## 二、安装经方诊室（诊所日常用）

诊室页面已经按诊所流程做好。拿到可用地址后，不必再装 Dify。

### 2.1 打开

1. 用 Chrome 打开经方诊室地址。
2. 第一次会看到「经方诊室不是自动医生」。
3. 阅读四条边界，点 **我是执业场景使用者，已理解上述边界**。
4. 右上角选 **医师** 或 **助手**。医师可看方证草稿；助手只采集和解释字段。

数据存在这台浏览器里（患者、方库增补、收款码、对话）。换电脑或清缓存会丢。不要填写身份证号。

### 2.2 需要云端 AI 时

舌象校验、检验解读、未勾选本机模型时的 AI 医生，走云端。在运行诊室的服务器上设置：

```bash
export XAI_API_KEY="你的密钥"
```

然后重启诊室服务。没有密钥时，规则辨证、方库检索、手工收费仍然可用，只是 AI 解释会提示暂不可用。

### 2.3 需要完全放在诊所电脑时（Ollama）

1. 安装 Ollama，并允许浏览器访问：

```bash
# macOS / Linux 示例
curl -fsSL https://ollama.com/install.sh | sh
export OLLAMA_ORIGINS="*"
ollama serve
```

Windows 在 Ollama 设置或系统环境变量里加入 `OLLAMA_ORIGINS=*`，然后退出并重新打开 Ollama。

2. 拉取模型：

```bash
ollama pull qwen2.5
ollama pull llava
```

`qwen2.5` 用于文字。看舌象、化验单、对话发图时，把模型名改成 `llava` 或其他视觉模型。

3. 打开诊室 **方库** → 展开 **本店增补 / 本地模型**：
   - 勾选 **使用本机模型**
   - 地址保持 `http://127.0.0.1:11434/v1`
   - 模型填 `qwen2.5` 或 `llava`
4. 右下角 **AI 医生** 标题会显示「本机 qwen2.5」。未勾选则显示「云端辅助」。

本机模型必须和打开网页的是同一台电脑。手机访问另一台电脑上的诊室时，把地址改成那台电脑的局域网 IP，例如 `http://192.168.1.20:11434/v1`，并确认防火墙放行 11434。

## 三、安装本仓库（规则、词表、方库样例）

```bash
git clone https://github.com/sandy01384007/tcm-inquiry-agent.git
cd tcm-inquiry-agent
```

目录：

| 路径 | 用途 |
|---|---|
| `SKILL.md` | 给支持 Skill 的助手加载 |
| `references/system-prompt.md` | 理论问答的系统提示 |
| `references/role-prompts.md` | 医师 / 助手差异 |
| `references/safety-guardrails.md` | 安全红线 |
| `references/local-library.md` | 方库 JSON 与本机模型 |
| `clinic/public/formulas.example.json` | 本店增补样例，导入前删掉示例方 |
| `clinic/public/formulas.local.json` | 空的本地方库 |
| `clinic/src/` | 诊室源码摘录（方库、AI 医生、主题） |
| `assets/glossary.json` | 概念词表 |

这不是一份带 `package.json` 的完整网站工程。日常开诊用第二节的诊室页面；仓库用来对照规则、导入方库和培训。

## 四、可选：用 Dify 做理论检索

只想做「问概念、带出处」，不做出方草稿时，再用 Dify。出方、煎煮、收费、舌象以经方诊室为准，不要两套提示词互相覆盖。

1. 安装 Docker，克隆 [Dify](https://github.com/langgenius/dify) 的 `docker` 目录，`cp .env.example .env` 后 `docker compose up -d`。
2. 浏览器打开服务器地址，创建管理员。
3. 设置 → 模型供应商：填写云端密钥，或添加 Ollama（`http://宿主机IP:11434`）。
4. 知识库名称自定。上传已脱敏的公开条文或自有笔记。分段建议 800 字、重叠 100。**不要上传受版权保护的完整课程原文。**
5. 创建聊天助手，把 `references/system-prompt.md` 贴进提示词。
6. 绑定知识库，Top K 设 6，分数阈值约 0.5，打开引用。
7. 增加变量 `user_role`，取值为 `医师` 或 `助手`，写法见 `references/role-prompts.md`。

Dify 这条线仍然禁止对患者开方、给毒性药剂量和针灸操作。

## 五、日常使用

### 5.1 医师看诊

1. 角色选 **医师**。
2. 打开 **看诊**。
3. 填写患者：姓名、年龄、性别、就诊日期、编号。
4. 按项填写主诉、起病、寒热、汗、二便、口渴、睡眠、胸腹、疼痛、脉、舌。
5. 舌象可拍照或从相册上传。AI 只做图像是否可用的质控，不能代替你看舌。
6. 点生成方证草稿。系统按症状标签给出最多 5 首候选，附八纲倾向和煎煮步骤。
7. 高风险方只显示执业限制，不显示可照抄的现代克数。
8. 你核定后，才可把草稿当作内部参考。不要把页面直接交给患者当处方。
9. 需要收款时点 **去收费**。

### 5.2 方库

1. 打开 **方库**，可按方名、证候、药味搜索。
2. **导入 JSON**：格式见 `formulas.example.json`。同 id 会覆盖。
3. **加载本地文件**：把方剂写进诊室站点的 `public/formulas.local.json` 后点此按钮。
4. **导出增补**：下载本店加过的方，换电脑时可再导入。
5. 展开 **本店增补 / 本地模型**，可手工加一首方，或接上节的 Ollama。
6. 只有医师可以 **清空增补**。内置经方不会被清掉。

### 5.3 检验

1. 打开 **检验**。
2. 选择体检报告、CT 或化验单，最多一次 3 张。
3. AI 摘录可见文字和需复核的点，并标明不是正式报告。
4. 急症影像（如活动性出血、大面积梗死描述）只提示尽快按急救流程处理。

### 5.4 收费

1. 打开 **收费**。
2. 先在页面保存诊所的微信、支付宝收款码（存在这台浏览器）。
3. 从看诊带入诊金，或手工加一行项目。
4. 选择微信、支付宝或现金。扫码收款后，由操作者点 **确认已收**。系统不自动到账，也不连接支付接口。
5. 可打印小票。作废需医师操作。

### 5.5 AI 医生

1. 点右下角红色的 **AI 医生**。按钮和标题处是会眨眼的卡通男医生。
2. 可以打字、点麦克风说话、拍照或上传图片。喇叭打开后会朗读回复。
3. 对话会带上当前患者、主诉、最近候选方和待收金额。
4. 回复是执业辅助，不是诊断，也不能让患者自行购药。
5. 助手角色下，AI 医生只帮助采集和解释，不核定方剂。

语音不可用时，改用打字。需允许浏览器使用麦克风，并用 Chrome 或 Edge。

### 5.6 助手

1. 右上角切到 **助手**。
2. 可以填患者和症状、查看字段含义、协助收费登记。
3. 不能核定处方，不能作废账单，不能清空本店方库。
4. 治疗决定交给医师。

### 5.7 记录

**记录**里可回看已保存的看诊草稿，并载入继续改。确认过的记录仍只是内部草稿。

## 六、上线前检查

- [ ] 未确认边界时进不了看诊
- [ ] 助手看不到可核定的处方操作
- [ ] 附子、承气类不出现家庭煎煮克数
- [ ] 胸痛、呼吸困难、昏迷等输入会提示急救
- [ ] 舌象、检验页写明「非正式诊断 / 非正式报告」
- [ ] 收款是「确认已收」，没有自动扣款
- [ ] 勾选本机模型后，AI 医生标题变为「本机 …」
- [ ] 取消勾选且配置了云端密钥时，对话能返回
- [ ] 导入一份测试 JSON 后能搜到，清空增补后消失

## 七、常见问题

| 现象 | 处理 |
|---|---|
| AI 医生说对话暂不可用 | 未设置 `XAI_API_KEY`，或改勾本机模型 |
| 本机模型连不上 | 确认 `ollama serve` 已开，地址含 `/v1`，并设置了 `OLLAMA_ORIGINS=*` |
| 发图没有看图 | 本机模型换成 `llava` 等视觉模型；云端需密钥 |
| 语音按钮无效 | 换 Chrome / Edge，并允许麦克风 |
| 换了一台电脑数据没了 | 方库用导出 JSON；收款码和病历在原浏览器，需重新录入 |
| 方库导入失败 | 文件须是 JSON，且含 `name`。先对照 `formulas.example.json` |
| 页面仍是旧的米色 | 强制刷新。当前主题是深松绿顶栏、鲜绿按钮 |

## 八、维护

| 频率 | 做什么 |
|---|---|
| 每日 | 看有没有把 AI 回复直接给患者 |
| 每周 | 抽几条看诊草稿，核对是否经医师改定 |
| 改方时 | 在方库导出一份 JSON 备份 |
| 换电脑 | 导入方库 JSON，重新上传收款码 |

理论检索若另接了 Dify：改提示词后用 `references/test-cases.md` 再测一遍「拒开方、拒急症、带免责声明」。
