# 经方问询助手（TCM Inquiry Agent）  
## 详细安装与使用手册

**版本**：1.0  
**适用对象**：中医小诊所管理员、医师、助理  
**预计完成时间**：有基础服务器经验约 1–2 天；纯小白约 3–5 天（含测试）

---

## 一、系统概述

**经方问询助手**是基于倪海厦课程蒸馏资料构建的中医理论检索与问诊辅助Agent。

**它能做的事**：
- 检索八纲、六经、药性、课程观点
- 辅助结构化问诊采集
- 返回带来源的理论参考

**它绝对不能做的事**：
- 开方、给剂量、指导针灸/艾灸操作
- 对真实患者做出诊断结论
- 替代执业医师决策

## 二、安装前准备

### 2.1 硬件与网络要求（最低）

| 项目 | 最低配置 | 推荐配置 |
|------|----------|----------|
| CPU | 4核 | 8核 |
| 内存 | 8 GB | 16 GB |
| 硬盘 | 50 GB SSD | 100 GB SSD |
| 网络 | 可访问大模型API 或 本地模型 | 稳定内网 + 可选外网 |
| 操作系统 | Ubuntu 22.04 / CentOS 7+ / Windows Server | Ubuntu 22.04 LTS |

### 2.2 需要提前准备的材料

1. 本方案全部交付文件（已打包在 `TCM_Agent_Complete_Package.zip`）
2. 大模型API Key（推荐通义千问 / DeepSeek / 月之暗面），或本地模型（Ollama + Qwen2.5）
3. 一台可长期运行的服务器或高性能电脑
4. 诊所内部账号体系（医师/助手区分）

### 2.3 推荐技术路线（小诊所）

**首选**：**Dify 私有部署**（开源、中文友好、工作流强、可完全本地）  
备选：FastGPT、自建 LangGraph + 前端

本手册以 **Dify** 为主进行说明。

## 三、详细安装流程

### 步骤1：安装 Docker 环境（约30分钟）

```bash
# Ubuntu 示例
sudo apt update
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable docker
sudo systemctl start docker
sudo usermod -aG docker $USER
# 重新登录使权限生效
```

验证：
```bash
docker --version
docker compose version
```

### 步骤2：部署 Dify（约40分钟）

```bash
# 创建目录
mkdir -p /opt/dify && cd /opt/dify

# 克隆官方仓库
git clone https://github.com/langgenius/dify.git
cd dify/docker

# 复制环境变量
cp .env.example .env

# 编辑 .env（重要）
# 建议修改：
# - SECRET_KEY（随机长字符串）
# - 数据库密码
# - 如使用本地模型，配置对应地址

# 启动
docker compose up -d

# 查看状态
docker compose ps
```

浏览器访问：`http://服务器IP`  
首次进入会要求创建管理员账号。

### 步骤3：配置大模型（约15分钟）

1. 登录 Dify 后台 → 「设置」→「模型供应商」
2. 添加你的模型（通义 / DeepSeek / OpenAI 兼容接口 / Ollama）
3. 填入 API Key 并测试连通
4. 设为默认模型

**本地模型示例（Ollama）**：
```bash
# 另一台机器或同机安装 Ollama
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5:72b   # 或更小的 14b/32b
# 在 Dify 中添加 Ollama 供应商，地址填 http://宿主机IP:11434
```

### 步骤4：创建知识库并导入资料（约1–2小时）

1. 进入 Dify → 「知识库」→ 「创建知识库」
2. 名称：`倪海厦中医课程`
3. 上传方式：
   - 直接上传已切分的文本（推荐先用 `scripts/rag_chunking.py` 处理）
   - 或上传原始 docx 后由 Dify 自动分段
4. 分段设置建议：
   - 分段最大长度：800
   - 分段重叠：100
   - 索引模式：高质量
5. 等待向量化完成

**元数据建议**（如平台支持）：
- 为每个文档添加 `permission_level`（public / restricted）
- 添加 `sub_domain`（八纲辨证 / 伤寒论 / 针灸 等）

### 步骤5：创建应用并写入 System Prompt（约20分钟）

1. 「工作室」→「创建应用」→ 选择「聊天助手」
2. 应用名称：`经方问询助手`
3. 打开「提示词」编辑框
4. 完整复制 `references/system-prompt.md` 中的内容并粘贴
5. 保存

### 步骤6：关联知识库与检索设置（约15分钟）

1. 在应用中「添加知识库」→ 选择刚创建的「倪海厦中医课程」
2. 检索设置：
   - Top K：6
   - Score 阈值：0.5
   - 开启「引用与归属」
3. 保存并发布

### 步骤7：配置角色变量与权限（约20分钟）

1. 在应用「变量」中添加：
   - 变量名：`user_role`
   - 类型：字符串
   - 可选值：医师 / 助手
2. 在提示词中引用（参考 `references/role-prompts.md`）
3. 如需更严格隔离，可创建两个应用：
   - `经方问询助手-医师版`（绑定全部知识）
   - `经方问询助手-助手版`（仅绑定 public 内容）

### 步骤8：开启日志与安全（约15分钟）

1. 开启对话日志
2. 如有 Webhook，配置推送到自建审计库（字段见 `references/audit-log.md`）
3. 设置访问密码或集成诊所现有账号体系

### 步骤9：发布与前端访问

- Dify 自带 WebApp 链接，可直接给医师使用
- 也可通过 API 对接诊所现有系统或微信小程序
- 建议诊所内网访问，减少外网暴露

## 四、日常使用流程

### 4.1 医师使用流程

1. 打开经方问询助手页面，确认角色为「医师」
2. **方式A：直接检索**  
   输入「什么是八纲辨证？」「太阳病主症」等 → 获得带来源的理论回答
3. **方式B：问诊辅助**  
   - 新建问诊  
   - 按页面提示填写主诉、寒热、二便、睡眠等  
   - 点击「生成理论参考」  
   - 阅读框架与课程观点  
   - 结合自身判断进行面诊决策
4. 结束前可保存对话记录（仅作参考，不作为病历替代）

### 4.2 助手使用流程

1. 确认角色为「助手」
2. 主要负责：
   - 帮助患者/医师采集结构化信息
   - 查询基础概念（八纲定义、常见术语）
3. 遇到复杂或治疗相关问题，直接转交医师
4. 不可要求 Agent 开方或操作指导

### 4.3 标准回答结构（每次都会看到）

1. 问题理解  
2. 相关理论框架  
3. 课程观点摘要（带来源）  
4. 建议进一步确认的问题  
5. **免责声明**（必须存在）

## 五、安全与红线（必须培训）

### 绝对禁止
- 让 Agent 开方或写剂量
- 询问「怎么扎」「怎么煎」「自己吃」
- 对急症患者继续理论讨论而不转诊
- 把 Agent 回复直接打印给患者当处方

### 急症处理
当输入中出现「胸痛、呼吸困难、昏迷、大出血、高热不退」等关键词时，Agent 会触发拦截并提示立即就医。此时应**立刻按诊所急救流程处理**，不再使用 Agent。

## 八、常见问题排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 无法访问页面 | Docker 未启动 / 端口未开放 | `docker compose ps` 检查，开放 80/443 |
| 回答不带资料 | 知识库未关联或检索阈值过高 | 检查知识库绑定与 Score 阈值 |
| 回答出现剂量 | Prompt 未正确加载或被覆盖 | 重新粘贴 System Prompt 并保存 |
| 助手能看到详细方证 | 权限变量未生效 | 检查 `user_role` 是否正确传入 |
| 响应很慢 | 模型负载高或网络问题 | 换更小模型或检查 API 延迟 |
| 中文乱码 | 编码问题 | 确认所有文件 UTF-8 上传 |
