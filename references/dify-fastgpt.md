# Dify / FastGPT 配置步骤（中医问询Agent）

**目标**：用低代码平台快速落地，适合小诊所无专职开发人员场景。

---

## 一、平台选择建议

| 平台 | 优势 | 适合场景 |
|------|------|----------|
| **Dify** | 开源、工作流强大、权限细、可私有部署 | 需要本地部署、数据不出院 |
| **FastGPT** | 知识库友好、中文体验好、插件丰富 | 快速验证、团队已有使用经验 |

两者均可完成本方案，以下以 **Dify** 为主说明，FastGPT 差异处单独标注。

---

## 二、Dify 配置步骤

### 1. 环境准备
- 推荐 Docker 一键部署（官方文档）
- 确保服务器内存 ≥ 8GB（知识库+模型）
- 配置域名与 HTTPS（诊所内网也可）

### 2. 创建应用
1. 进入「工作室」→「创建应用」→ 选择「聊天助手」或「工作流」
2. 应用名称：`经方问询助手`
3. 选择模型：推荐通义千问 / DeepSeek / 本地 Qwen2.5

### 3. 写入 System Prompt
- 打开「提示词」编辑
- 完整复制 `references/system-prompt.md` 中的 Prompt
- 保存

### 4. 知识库配置
1. 创建知识库「倪海厦中医课程」
2. 上传已切分好的文档（或先用 `scripts/rag_chunking.py` 处理后上传）
3. 分段设置：
   - 分段标识：按标题 / 课次
   - 分段最大长度：700–900 字符
   - 重叠：80–100
4. 索引模式：高质量（推荐）
5. 元数据：导入 `scripts/generate_metadata_csv.py` 中的字段（file_id、permission_level、sub_domain 等）

### 5. 检索设置
- 检索模式：混合检索（向量 + 全文）
- Top K：5–8
- Score 阈值：0.5 以上
- 开启「引用与归属」：强制显示来源

### 6. 变量与开场白
- 添加变量：`user_role`（医师 / 助手）
- 开场白示例：
  ```
  您好，我是经方问询助手。
  我可以帮您检索八纲、六经、药性等理论参考。
  请注意：我不能开方、不能给出剂量或操作指导，所有内容仅供学习参考。
  请先选择您的角色，或直接描述需要查询的理论问题。
  ```

### 7. 工作流增强（推荐）
- 节点1：角色判断（根据 user_role 过滤 permission_level）
- 节点2：高风险关键词检测（若命中 → 直接返回拦截话术）
- 节点3：知识库检索
- 节点4：LLM 生成（注入 System Prompt）
- 节点5：后处理追加免责声明

### 8. 发布与权限
- 发布为 WebApp / API
- 设置访问权限：诊所内部账号
- 开启对话日志（用于审计）

## 三、FastGPT 对应配置要点

1. 创建「知识库」→ 上传文档 → 选择「增强处理」
2. 应用类型选择「知识库问答」
3. 系统提示词粘贴同一份 System Prompt
4. 在「高级编排」中增加「条件分支」实现角色过滤与高风险拦截
5. 引用设置打开「显示来源」

---

## 四、权限差异化实现（关键）

**方法一：变量控制（简单）**
- 前端传入 `user_role=医师` 或 `助手`
- Prompt 中写：
  ```
  当前用户角色：{{user_role}}
  若角色为「助手」，restricted 内容只返回摘要与来源，不展开详细理论。
  ```

**方法二：多知识库（更安全）**
- 创建两个知识库：`public_kb` 与 `restricted_kb`
- 医师应用绑定两个库，助手应用只绑定 public_kb

---

## 五、高风险拦截实现

在工作流最前面增加「代码节点」或「条件分支」：

```python
# 伪代码示例
risk_keywords = ["剂量", "怎么煎", "怎么扎", "自己吃", "附子", "放血", "开方"]
if any(kw in user_query for kw in risk_keywords):
    return "根据安全规则，我无法提供可执行的操作或剂量建议。请咨询执业中医师面诊。"
```
